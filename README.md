# Spotlight · 视频单人聚焦

选中一个人，整段视频只让他清晰——其余所有人和背景一律虚化。
手持跟拍、镜头运动、目标走出画面再回来，都尽量跟住同一个人，不中途换人。

全程跑在 Apple Silicon 上：分割用 **SAM 2.1（MLX 原生，走 Metal GPU）**，
合成与编码交给 **ffmpeg + VideoToolbox 硬件编码**。不需要联网，不上传任何数据。

---

## 快速开始

```bash
cd spotlight
./启动\ Spotlight.command        # 双击也可以
```

首次运行会自动建虚拟环境、装依赖、下载「均衡」档权重，然后打开
<http://127.0.0.1:8760>。

界面上：**导入视频 → 拖进度条到目标最清楚的时刻 → 在人物身上点一下（或拖个框）
→ 立刻看到抠像预览 → 开始处理 → 在线预览与下载**。

成片出来后可以切成 **成片 / 原片 / 左右对比** 三种视图对照着看；
跑偏了不用重来，拖到出问题的那一帧补个修正点即可（见下一节）。

### 三个 .command 脚本

| 文件 | 作用 |
|---|---|
| `启动 Spotlight.command` | 手动启动服务（前台运行，关掉窗口即停） |
| `部署为开机自启.command` | 注册成 macOS 登录自启服务，**以后每次开机自动可用** |
| `停止并卸载服务.command` | 停掉服务并取消开机自启 |

开机自启走的是 LaunchAgent（`~/Library/LaunchAgents/ai.spotlight.server.plist`），
带 `KeepAlive`，进程意外挂掉会自动拉起；日志写在 `work/logs/`。

> **为什么注册得你自己双击**：从 WorkBuddy 这类受控环境内部发起的进程执行
> `launchctl` 会被系统拒绝（报 `5: Input/output error`），只有你自己的终端
> 才有权限注册 LaunchAgent。脚本会自己生成 plist 并注册，你只要双击一下。

### 服务地址与端口

默认监听 `127.0.0.1:8760`，**只绑本机回环，局域网里其它设备访问不到**，数据不出本机。

```bash
SPOTLIGHT_PORT=9000 ./部署为开机自启.command   # 换端口部署
python -m spotlight.cli serve --port 9000      # 换端口临时跑
```

`work/uploads/` 里会累积上传的视频，服务启动时会自动清理旧的
（保留最近 12 个、超过 7 天的删掉）。

### 命令行

```bash
python -m spotlight.cli doctor                     # 环境自检
python -m spotlight.cli download --preset balanced # 下载权重

# 坐标默认是归一化的 0~1；加 --coords px 则用像素
python -m spotlight.cli run -i in.mp4 -o out.mp4 \
    --frame 30 --box 0.46,0.38,0.66,1.0 --preset balanced

# 点选（+ 为正面，- 为排除）
python -m spotlight.cli run -i in.mp4 -o out.mp4 \
    --frame 30 --point 0.52,0.45 --point -0.70,0.60

# 跑到一半发现跟偏了？在出问题的那一帧补一个修正点，重新跑
python -m spotlight.cli run -i in.mp4 -o out.mp4 \
    --frame 30 --point 0.52,0.45 --anchor 480:0.55,0.50

# 只处理其中一段（长视频先试一段）
python -m spotlight.cli run -i in.mp4 -o out.mp4 \
    --frame 30 --point 0.52,0.45 --range 0:900 --preset turbo
```

## 清除旁人

除了「只让目标清晰」，还可以**把除目标外的所有人抹掉**，用重建出来的背景补上。
界面上勾选「清除旁人」，命令行加 `--remove-people`。

```bash
python -m spotlight.cli run -i in.mp4 -o out.mp4 --frame 0 --point 0.55,0.65 \
    --remove-people --preset balanced
```

> **清除旁人 ≠ 虚化。** 清除模式下，整段画面**保持清晰**——背景是重建出来的真实内容，
> 不再做虚化 / 压暗 / 去色，也不受「存在门」影响（目标离场时**不会**切回原片、让被清除的人
> 重新冒出来）。界面勾选「清除旁人」后，背景类滑块（虚化 / 压暗 / 去色 / 柔光）会自动禁用。
> 如果想在清除的同时再叠加虚化，请分两步：先清除导出，再把成品当输入跑一次虚化模式。

```bash
# 旧写法（效果参数清零）已不再需要——清除模式默认就是清晰背景，下面等价但多余：
python -m spotlight.cli run -i in.mp4 -o out.mp4 --frame 0 --point 0.55,0.65 \
    --remove-people --blur 0 --brighten 0 --glow 0 --bg-dim 0 --bg-desat 0
```

需要先下一个修复模型（208 MB）：

```bash
python -m spotlight.cli download --preset lama
```

### 它是怎么做的

1. **找出所有人** —— 用系统内置的人像分割（`VNGeneratePersonSegmentationRequest`，
   跑在 ANE 上、约 35 ms/帧、不需要下载模型）拿到「全体人员」掩码。
2. **保住目标** —— 见下一节。这一步比看上去难，也是最容易出「诡异结果」的地方。
3. **重建背景** —— 运动补偿的时域累积。按段（默认每 32 帧换一张板）在板中心帧坐标系里
   把帧对齐叠加，**只取完全没有人的像素**，得到一张干净的背景板。
   段内共用一张板，所以**段内完全时间一致、不会闪**。
4. **稳健估计** —— 得到加权均值后再做一遍**截尾**：只采信偏离初值不超过 40 灰阶的样本。
   这一步专门对付「运动估计把某些帧对齐偏了」，实测能把背景一致性误差从 6.0 降到 4.9 灰阶。
5. **补空洞** —— 用**邻近段板互相补**，剩下的交给 LaMa：
   - 某块背景在这几十帧里被挡着，但在隔壁时段露过 → 从邻近的段板搬过来。
     邻近板之间只隔几十帧，漂移小，搬过来的是对的内容。
   - 实在没人见过的 → **LaMa**（ONNX，走 CoreML/ANE）去补。

   > 这里踩过一个坑：一开始是用**一张全片板**（以某一帧为参考系累积整段视频）来补洞。
   > 看起来很美——空洞能从 27% 降到 4%。但那块板要跨几百帧累积单应链，
   > **漂移会累积到十几像素**，映射回目标帧时已经是错位内容：实测平均误差 26 灰阶、
   > 整体偏暗 10 灰阶。补进去就是重影和脏块。换成邻近段板后，误差降到 3.8~12 灰阶、
   > 亮度差只剩 0.7~4，代价是空洞多了一些（交给 LaMa）。

### 补洞模型：快速 (LaMa) vs 高质量 (扩散)

清除旁人是在**背景板**上补洞的，而背景板「每段一张、段内共用」，所以补洞成本按
**段数**摊销，不是逐帧——一部短视频也就 5~9 张板。因此即便用慢的扩散模型，
整段也只多花几分钟，完全可作为「质量」档。

| 模型 | 命令 | 速度 | 质量 | 依赖 |
|---|---|---|---|---|
| **LaMa**（默认） | `--clean-inpaint-model lama` | 快（每段 <1s） | 内容是「合理但不对」，砖墙/树叶/人群后方易糊 | ONNX + ANE，已内置 |
| **扩散** (SD inpainting) | `--clean-inpaint-model diffusion` | 慢（每段几十秒，仅 M 系列 GPU/MPS） | 能长出对的纹理，复杂背景明显更真 | 需 torch+diffusers，数 GB 权重 |

下载扩散权重（需能访问 HuggingFace 的网络）：

```bash
python -m spotlight.cli download --preset diffusion
```

界面里勾选「清除旁人」后会多出「补洞模型」下拉，可在「快速」和「高质量」间切换；
本机没下载扩散权重时选「高质量」会给出提示。

### 保住目标：比看起来难

`要抹掉的区域 = 全体人员 − 目标` 这个式子看着简单，但直接减会出问题：

**SAM2 经常只切出目标的一部分**——典型是**只切了身体、没切到头部**（头被 VR 眼镜、
口罩、帽子这类物体挡住时尤其明显）。这时候「目标掩码」只剩身体，
**头就会被当成「别人」抹掉**，画面里出现「身体还在、头被换成背景」的诡异结果。

所以保护范围分三层兜，从精确到宽松：

1. **人体检测框** —— 用系统的人体矩形检测找到目标所在的框，把框内的人员像素一并保留。
   检测框天然包含头部，而且一个人一个框。**在合格的框里挑最小的那个**——
   目标离镜头近时检测器会给出几乎覆盖全画面的大框，用它就把旁边的人一起保护掉了。
2. **连通域整块保留** —— 目标和它的某个部位在人员掩码里可能是连着的，
   只要某个连通域和目标有足够重叠，就整块保下来。
3. **外接框小幅外扩** —— 兜底。

三层都受一个**总量预算**约束（目标掩码面积 × 2）。这是整套逻辑的保险丝：
人像分割经常把目标和旁边的人糊成**一整个大连通域**（实测一个场景里 65% 的画面
是一个连通域），没有预算的话任何一条兜底规则都可能把半个画面保下来，等于什么都没清。

整体方向刻意偏保守：**宁可少抹掉一个人，也不能把目标自己弄坏**——
少抹一个只是效果打折，把目标弄坏则整个结果作废。

### 最关键的一个参数：取样窗口

单应矩阵只能对齐一个平面，走廊、街道这类有纵深的场景必然存在视差，
**帧距越远视差越大、错位越明显**。所以每张板只取中心帧前后各 16 帧的样本
（`--clean-window`，默认 16）。这个值实测是**重影与空洞的平衡点**：

| 取样窗口 | 背景一致性误差 | 空洞 |
|---|---|---|
| ±12 | 4.00 | 12.2% |
| **±16** | **3.57** | 11.6% |
| ±24 | 4.39 | 11.2% |
| ±48 | 7.17 | 8.9% |
| ±64 | 7.29 | 8.6% |

窗口开大换来的那点空洞收益，远不及它带来的重影代价（误差翻倍）。
**把窗口从 64 降到 16，误差直接减半。**

### 什么时候效果好

- **背景在别的时刻露出过**（路人在走动）—— 这是最关键的
- **镜头有移动** —— 能拍到被挡住的地方
- **场景纵深不大** —— 单应矩阵只能对齐一个平面
- **人在画面里占比不高**（典型场景 10~20%）

### 已知限制（说实话）

- **密集人群效果明显下降。** 当人在画面里占 40% 以上时，等于要「编」掉小半个画面。
  实测在一个 46% 被人占满的走廊场景里：段板空洞 27%（那些位置整段视频里都没露过背景），
  只能交给 LaMa 去编，能看出明显的重影和脏块。
- **人像分割本身会失手。** 实测有的素材上它把 65% 的画面判成「人」，
  而且是**一整个连通域**——这时候「抹掉所有人」等于抹掉大半屏。
  所以保护目标那套逻辑里必须有个总量预算兜着，否则一不小心就变成「什么都没清」。
- **视差是最主要的误差来源。** 走廊、街道这类有明显纵深的场景，近处和远处的运动不一致，
  单应矩阵对齐了一处就错开另一处。缩短取样窗口能大幅缓解（见上表），但没有根治——
  真正的解法是逐像素的深度感知对齐，那是另一个量级的工程量。
- **远处的小人会被漏检。** 人像分割对又小又远的人召回有限，那些像素看起来像背景、
  其实还是人，累积后就是残影。目前靠把人员掩码膨胀 9 像素缓解一部分。
- **被永久挡住的区域只能靠模型编。** 如果某块背景在整段视频里从没露过，
  就只能让 LaMa 补——补出来是「合理但不对」的内容。
- **速度**。这一步在**源分辨率**上跑（避免整段被降分辨率拖糊），
  再加上人员分割、运动估计和 LaMa 推理，整体大约相当于跟踪本身的两倍耗时。
  先用 `--range 0:300` 试一小段再决定要不要跑全片。

### 调参速查

| 参数 | 默认 | 作用 |
|---|---|---|
| `--clean-window` | 16 | 取样窗口（帧）。**最重要的一个**：调大→空洞少但重影重 |
| `--clean-segment` | 32 | 每多少帧换一张背景板 |
| `--clean-dilate` | 7 | 移除掩码膨胀像素，防止人物边缘残留一圈 |
| `--no-inpaint` | 关 | 不用 LaMa，空洞会留黑（一般别关） |

> 结论：这是个「锦上添花」的功能，适合**把偶尔路过的几个人清掉**，
> 不适合**把密集人群从画面里完全抹除**。后者本质上是视频修复的研究问题，
> 单靠单应对齐 + 图像修复模型做不到干净。

## 跟偏了怎么修

这是最容易遇到的场景：整段大部分都对，就是某一段跟错人或者丢了。
**不需要从头重来**，回到出问题的那一帧补一个修正点即可：

1. 把成片倒到出问题的时间点，记下大概是第几帧；
2. 回到上面把进度条拖到那一帧（<kbd>←</kbd> <kbd>→</kbd> 可以逐帧微调）；
3. 在正确的人身上点一下 —— 这会生成一个**修正锚点**（列表里会显示「修正 第 N 帧」）；
4. 再点「开始处理」。这次 SAM2 传播到第 N 帧时会直接采用你的修正，前后两个方向都会跟着更新。

界面上每个锚点都能单独删除（点标签上的 ×），<kbd>⌘Z</kbd> 撤销上一个点。
第一个锚点叫「主锚点」，它决定了初始的目标外观模板。

## 效果参数

界面上的滑块对应命令行的开关，默认值就是「虚化 + 提亮主体」这一档：

| 参数 | 命令行 | 默认 | 说明 |
|---|---|---|---|
| 背景虚化 | `--blur` | 26 | 高斯 sigma，越大越虚 |
| 主体提亮 | `--brighten` | 0.055 | |
| 主体对比 | `--contrast` | 1.07 | |
| 柔光强度 | `--glow` | 0.22 | 主体上的柔光叠加，0 关闭 |
| 边缘羽化 | `--feather` | 3 | 掩码过渡的柔和程度 |
| 背景压暗 | `--bg-dim` | 0.02 | 如 `-0.08` 压得更狠 |
| 背景去色 | `--bg-desat` | 0.12 | 0~1 |
| 主体锐化 | `--sharpen` | 0 | 0 关闭 |

> 目标不在画面里的那些帧会**原样输出**，不会被整体虚化——这一路「存在门」
> 让画面看起来自然得多。

## 处理档位（M5 / 24GB 实测）

| 档位 | 模型 | 推理分辨率 | 速度 | 适用 |
|---|---|---|---|---|
| `turbo` | Hiera-Tiny | 640 | ~10 帧/秒 | 长视频先扫一遍看效果 |
| `fast` | Hiera-Small | 768 | ~5.9 帧/秒 | 快出片 |
| `balanced` | Hiera-Small | 1024 | ~2.9 帧/秒 | 日常推荐 |
| `quality` | Hiera-Base+ | 1024 | ~1.6 帧/秒 | 边缘最干净 |

**速度主要由推理分辨率决定，而不是模型大小。** 记忆库的交叉注意力开销随
分辨率四次方增长，所以「把分辨率从 1024 降到 768」比「把模型换小一号」划算得多
（前者快一倍，后者只快 7%）。实测 768 与 896 的掩码几乎一样，而 896 要慢 50%，
所以 `fast` 档直接定在 768。

粗算：`帧数 ÷ 速度 = 处理秒数`。一段 10 秒 25fps 的 1080p 素材约 250 帧，
均衡档约 1.5 分钟。

## 选人的两个关键细节

**1. 点在身体上，别只点头部。**
在拥挤画面里给一个点，SAM2 很容易只把**头部**切出来（头是个更「干净」的对象），
结果就是只有脸清晰、身体被虚化。所以界面上提示点在胸口/躯干上。

**2. 程序会自动兜底。**
即使你只点了头，程序也会先用人体检测估出这个人的大致范围，
如果掩码没填满这个范围，就换成「人体框」再下一次提示，取覆盖更好的那个。
实测男孩那一段素材从覆盖 10% 提到 56%——从「只有脸清楚」变成「整个人清楚」。
找不到人体框时（密集人群里检测会漏），才按你的选择原样分割，并在界面上说明。

## 为什么不会中途换人

SAM2 的流式记忆库本身就擅长短时遮挡和镜头运动，但会以三种方式失手：

* **掩码塌缩** —— 在拥挤或遮挡场景里退化成只覆盖头部的一小块，或者干脆变空；
* **交叉穿越** —— 掩码整体跳到另一个人身上，而面积、位置看起来都还「合理」；
* **长时间出画再回来** —— 记忆衰减，回来时锁定到旁边相似的人。

关键是**把两类信号分开用**，因为它们各自都判断不准：

| 信号 | 它回答的问题 | 它的盲区 |
|---|---|---|
| 几何（面积/位置/模型自报置信度） | 掩码本身好不好？ | 分不清「人被挡住了所以只剩一半」和「模型塌缩了」 |
| 外观（特征向量比对） | 还是不是同一个人？ | 人没认错但只框了半个人时，它发现不了 |

合起来用就清楚了：

**几何信号决定「什么时候该重新锚定」，外观信号决定「允许锚定到谁」。**

具体流程：

1. **几何检查**：掩码为空、面积突变、质心瞬移、或者 SAM2 自报的掩码置信度
   过低（这一项直接从模型解码器里截出来，比面积启发式靠谱得多）→ 标记可疑。
   同时会丢掉掩码里的零散小碎块，避免画面别处冒出一小块莫名其妙的清晰区域。
2. **外观看门狗**：每 6 帧把当前目标区域的外观特征与模板比对一次。
   这一道专门抓「掩码悄悄跟到别人身上」——它抓的是**身份**，不是形状。
3. **重锚定**：任一路信号持续异常超过耐心值，就把画面里所有可能是人的框找出来
   （人体矩形 + 人脸 + 人体姿态三种检测器合并，实测在密集人群里候选池
   从 1 个提升到 8~10 个），逐一算外观特征，**只有与模板足够像的那个才允许
   作为新锚点**；都不够像就继续保持「丢失」状态。
4. **丢失时不硬撑**：目标确认不在画面里时，掩码清零，同时逐帧渐变地把
   「存在门」拉到 0——整帧恢复原样，不会有「啪」地一下的硬切。

外观模板只在「健康且像自己」的帧上做 EMA 更新，不会被背景或别人污染；
目标长时间丢失后，还会先清空被污染的记忆再重新锚定。

实测（460 帧密集人群、镜头持续运动、目标反复被人挡住）：
丢失帧 **413 → 48**，重锚定 **80 → 18**，且全程锁定的是同一个人。

关闭身份守卫：界面上的开关，或命令行 `--no-reid`。

### 三处关键工程取舍

**帧不放在内存里。** 原版 SAM2 的 `init_state(video_path)` 会把整段视频解码成
`float32` 的 1024×1024 张量一次性堆在内存里（1080p 的 250 帧约 3 GB，长视频直接爆）。
这里把帧写成磁盘上的 `uint8` 文件，推理时按帧读取。

**掩码也不放在内存里。** 每帧掩码 1280×720 是 0.92 MB，300 秒素材就是 8.3 GB，
而且补齐空洞、跳帧插值还会各再复制一份。掩码同样落磁盘。
这里有个反直觉的坑：**用 `np.memmap` 写掩码时，脏页会计入进程 RSS**
（实测写 11 GB 掩码，RSS 涨到 8.8 GB，在 24 GB 的机器上依然危险）。
换成 `pwrite`/`pread` 走普通文件 I/O 后，数据落在内核页缓存里、不计入进程内存，
同样的写入量 **RSS 增长为 0**。

**状态边跑边裁。** 每帧的 `maskmem_features` 约 17 MB，原实现会一直累积
（1000 帧就是 17 GB）。但读一下 `condition_with_memories` 就会发现，它实际只用到
最近 7 帧的掩码记忆和最近 16 个 object pointer，更早的非条件帧根本不会被读取。
因此可以安全地裁到最近 32 帧——既保住原生的时序连续性（不用分块、不会因为
重新播种而漂移），又不会让内存随帧数线性增长。

结论：**进程自己持有的内存与视频长度无关。** 实测往掩码存储里写 11 GB 数据，
峰值 RSS 一点没涨（0 MB）；4 倍长度的视频跑完，峰值 RSS 从 799 MB 到 1620 MB，
多出来的那部分全是**帧的只读页缓存**——它是可回收的文件页、不是泄漏，
系统在内存紧张时会自己回收。真正会随帧数线性增长的两样东西（每帧掩码、
每帧记忆特征）都已经处理掉了。

## 已知限制

- **重锚定依赖系统人体检测的召回率。** 在极密集且人很小的画面里，
  候选池可能漏掉目标，这时会保持「丢失」而不是跟错人。界面上可以随时
  重新点选目标来手动接管。
- **背景虚化是全局均匀的**，没有做深度估计，所以不是真正的「景深」，
  而是类似「人像模式」的整体虚化。
- **推理分辨率低于 1024 时边缘会略粗**（`turbo` / `fast` 档），
  但因为最终会做羽化过渡，实际观感差异不大。
- 竖屏视频、变帧率视频都支持（解码时会统一成恒定帧率），
  但超长视频建议先用 `turbo` 档扫一遍确认选人是否正确。
